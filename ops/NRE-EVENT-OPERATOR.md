# NRE Shadow — Regional Game Events & Discord Publishing

This is one **GitHub Actions** Discord event operator (twice an hour, best-effort). The separate **one** ChatGPT NRE Shadow hourly task maintains the system and reviews failures. No individual ChatGPT reminder is needed per event, game or region.

## Where events go: opt-in server registry

ops/server-targets.json starts with an empty servers list because no Discord guild/channel IDs have been authorized or verified. Adding an entry enables publishing **only** to that server and only for the games and regions it opts into. Every server must have an administrator's permission, and the bot must be installed with Manage Events plus View Channel, Send Messages, and Read Message History in its announcement channel.

Replace the example IDs below with actual Discord IDs in ops/server-targets.json through a reviewed change. **This is documentation, not a configured live destination:**

    {
      "servers": [
        {
          "id": "nre-empire",
          "enabled": true,
          "guildId": "YOUR_REAL_DISCORD_SERVER_ID",
          "announcementChannelId": "YOUR_REAL_EVENTS_CHANNEL_ID",
          "games": ["kiomet", "openfront", "netquel", "mk48"],
          "regions": ["asia", "europe", "americas"],
          "recruitmentEnabled": true,
          "recruitmentChannelId": "YOUR_OPTED_IN_RECRUITMENT_CHANNEL_ID",
          "recruitmentIntervalHours": 72
        }
      ]
    }

For a China-focused NRC server, use only regions:["asia"] and the games its community actually plays. Other NRE/TIC/partner servers may be included only if their administrators affirmatively permit this bot to publish. Do **not** create events in unrelated servers without that permission. One-off events defined in ops/events.json require an explicit targetServerIds array naming the server entry or matching game/region metadata. Unspecified one-offs never broadcast to every server by default.

## One-time credentials / connection

1. Use an existing NRE bot that you control, already added to each participating server with **Manage Events**. It needs View Channel, Send Messages and Read Message History in approved events and recruitment channels. It need not run on your Windows PC because GitHub Actions uses the Discord REST API directly.
2. In the NRE GitHub repository go to **Settings → Secrets and variables → Actions → Secrets**. Add repository secret **NRE_DISCORD_BOT_TOKEN**. **Never paste the token into chat, a file, a commit, or an issue.**
3. Add servers and announcement-channel IDs to the version-controlled ops/server-targets.json only after authorization. Guild/channel IDs are not passwords. The old unused NRE_DISCORD_GUILD_ID and NRE_DISCORD_ANNOUNCEMENT_CHANNEL_ID repository variables are no longer read by the multi-server operator.
4. Run **Actions → NRE Discord Event Operator → Run workflow → dry_run=true** to review the event queue and routing without contacting Discord.
5. Verify the successful scheduled runs and Discord Scheduled Events in each permitted server before telling members that publishing is live.

If no authorized servers are configured or no bot token is stored, the workflow reports **0 published** rather than pretending a Discord event exists.

## Announcements and opt-in recruitment

- The operator creates an external Discord Scheduled Event for an approved game session up to 14 days ahead.
- Each server's dedicated events channel receives a normal announcement within 72 hours of the event, plus a 24h/3h/1h reminder if checks fall in the corresponding delivery window.
- Each server may opt into a separate **recruitment channel**. At most one recruitment invite every 72 hours, with up to three actual upcoming Discord Event links for interested players. It never cold-DMs members or posts to unaffiliated servers.
- Messages use Discord allowed_mentions.parse=[] to suppress @everyone, @here, role and user pings. Recurring posts are keyed by event and server in one persistent GitHub issue ledger. The operator also searches recent Discord events/messages to reduce duplicate delivery.
- Game hosts, player recruitment outcomes, attendance and actual matches **cannot be fabricated**. Bots can provide RSVPs and invitations, not live volunteers. Track turnout before increasing frequency.

## Limits and reliability

GitHub Actions scheduled triggers may be delayed or skipped under load, and after 60 days of public repository inactivity may be disabled. Discord's own RSVP notifications provide additional coverage. A failed bot permission check requires an admin fix; do not bypass access controls. The operator does not automatically merge code, change passwords or authorize a new server. Any real-time game moderation/hosting requires the game-specific bot or human host to be reachable. There is no auto-DM, unsolicited outbound recruitment or fabricated activity.

## Verification

Run node --test ops/nre-events.test.mjs ops/nre-event-program.test.mjs ops/nre-servers.test.mjs. In GitHub, inspect the relevant NRE Discord Event Operator PR workflow and on-main workflows. Until a configured authorized target is verified, a passing CI job means **the implementation tests passed**, not that a Discord event was published.
