# NRE regional event host playbook

**Status:** internal operating template. This document does not certify that any Discord server, game bot, volunteer host or event is active. Do not announce a session as staffed until a real person confirms.

## One host, one game, one region

Each event has a single game and a single 6–7 PM local region. The host should be available 10 minutes before and 10 minutes after the session. Assign a backup host when practical. Keep the actual match flexible if fewer players arrive. Do not combine game series simply to inflate RSVP counts.

| Local time | Host action |
| --- | --- |
| 5:45–5:55 PM | Check server permissions, game lobby, invite accessibility and whether there is a real host |
| 5:55–6:00 PM | Welcome attendees in the designated game channel; post lobby instructions once |
| 6:00–6:10 PM | Introduce new players, explain game rules and team assignments; no pressure to speak |
| 6:10–6:50 PM | Play; facilitate fair teams and answer newcomers' questions |
| 6:50–7:00 PM | Wrap up, invite opt-in feedback and share the next **confirmed** session |
| Afterward | Record actual turnout and incidents; post one short recap if appropriate |

## Low turnout protocol

- **0 players:** do not fabricate a match. Mark as no-show; no victory claims or synthetic conversation. Ask whether the day/time/game should change.
- **1–2 players:** offer a friendly onboarding/tutorial or casual conversation, with consent; do not pretend a tournament happened.
- **3+ players:** run the format that actually works for that game and player count. Record attendance accurately.
- **No host:** mark the event unstaffed, attempt to recruit an authorized volunteer, and postpone/cancel if nobody can facilitate safely.

## Invitation copy (for an approved server/channel only)

**Kiomet:** “Kiomet players: we're organizing a regional NRE session at 6 PM local time. New players welcome. RSVP through the Discord Scheduled Event to help us plan teams. If you can host, let an organizer know.”

**Openfront:** “Openfront strategy session this weekend: team up, learn the basics and play with the NRE community. RSVP in the event listing so we know who is interested.”

**Netquel:** “Netquel session at 6 PM local time. Whether you're experienced or just checking it out, join the NRE event and find a group to play with.”

**MK48.io:** “MK48.io fleet meetup: join other NRE players for a coordinated hour of naval gameplay. RSVP to the scheduled event; we'll share the lobby details before the start.”

Only publish the relevant game's copy in an authorized channel with a real event link. No cold DMs, misleading scarcity, fake giveaways, member scraping, automated mass invites or ping storms.

## Lightweight attendance and recruitment tracking

Store a **single row per real event occurrence** in an internal staff-maintained sheet, issue or future bot database. Suggested fields: event ID, game, region, local start, host confirmed (yes/no), RSVP count observed, actual unique attendees, new attendees (voluntary count), returning attendees, event held/cancelled/no-show, duration, issues, next action. RSVP count is **not** actual attendance. Never publish personally identifying attendance lists without permission.

For the first four weeks, track:
- **Host coverage:** staffed sessions / scheduled sessions.
- **Attendance:** real unique participants per event, including zeroes.
- **Conversion:** actual attendees / RSVPs, when RSVPs are measurable.
- **Retention:** participants who voluntarily return to a later event, if privacy-safe and opt-in.
- **Recruitment effectiveness:** genuine joins attributable to approved event invitations, not message volume.

Review weekly. Pause weak sessions instead of increasing automated announcements. Prioritize the game/region with the strongest combination of host coverage, turnout and newcomer interest. One real six-player match is better than nine empty event cards.

## Escalation

A host can ask an NRE moderator for help with disruption, harassment or unsafe content. Moderators apply existing server rules; the event operator should never assign punishments automatically based solely on RSVP or attendance. For missing permissions or Discord publishing failures, track the blocker in issue #5 and do not imply that events have been delivered.
